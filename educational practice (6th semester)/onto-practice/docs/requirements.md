# Требования

## 1. Цель

Прототип системы автоматической/полуавтоматической проверки документов (приказов о направлении на практику) на соответствие регламенту кафедры через **OWL-онтологию + SWRL-правила** и встроенный ризонер.

Регламент (источник истины): «Методические рекомендации по организации и проведению практики обучающихся ФИТ» НГУ (направления 09.03.01 / 09.04.01).

## 2. Сценарии использования

### UC-1. Построение онтологии из регламента (выполняется один раз)
Аналитик запускает скрипт `scripts/build_ontology.py`. Скрипт через LLM (OpenRouter) извлекает черновик сущностей, свойств и правил из текста регламента, генерирует `regulations/practice.owl`. Аналитик доводит черновик в Protégé.

### UC-2. Проверка приказа (основной runtime-сценарий)
Пользователь открывает веб-интерфейс, загружает PDF приказа о направлении на практику, выбирает регламент (по умолчанию — единственный). Система парсит PDF, применяет SWRL-правила через ризонер (HermiT через owlready2), показывает HTML-отчёт: список студентов, обнаруженные нарушения с пояснениями, поля, которых не хватает.

## 3. Декомпозиция на фичи

### MUST (входит в MVP)

| ID | Фича | Описание |
|---|---|---|
| F-01 | Build-time извлечение онтологии | LangChain + OpenRouter извлекает классы/свойства/правила из текста регламента → `regulations/practice.owl` (черновик) |
| F-02 | Ручная доводка онтологии | Готовый `regulations/practice.owl` после ручной правки в Protégé. Включает 5–10 SWRL-правил MVP-уровня |
| F-03 | Парсинг PDF приказа | PyMuPDF рендерит страницы → LLM (OpenRouter, vision) извлекает таблицу студентов + поля шапки |
| F-04 | Загрузка фактов в OWL-модель | Извлечённые факты создаются как individuals в копии онтологии перед запуском ризонера |
| F-05 | Запуск ризонера | owlready2 + HermiT, обнаружение нарушений правил, классификация инстансов |
| F-06 | Отчёт о соответствии | HTML-отчёт: общая сводка + per-student нарушения с человекочитаемым описанием |
| F-07 | Веб-интерфейс | FastAPI + Jinja2 + HTMX. Страницы: загрузка PDF, прогресс, отчёт |
| F-08 | Плагинная структура регламентов | `regulations/*.owl` подгружаются автоматически. Добавление нового регламента не требует правки ядра |

## 4. Скоуп MVP — правила для проверки

В черновике онтологии должны быть как минимум следующие SWRL-правила (или их аналоги через class expressions):

| ID | Правило | Источник в регламенте |
|---|---|---|
| R-01 | Все обязательные поля заполнены: ФИО, группа, зач.№, место, адрес, ФИО руководителя, кафедра | Структура приложений 1–3 (стр. 28–33) |
| R-02 | Направление подготовки ∈ {09.03.01, 09.04.01} | стр. 2 |
| R-03 | startDate ≤ endDate | здравый смысл |
| R-04 | Дата приказа не позднее чем за 30 дней до startDate | стр. 9 («не позднее чем за 1 месяц до начала практики») |
| R-05 | Каждому студенту назначен ровно один руководитель от НГУ | стр. 6 |
| R-06 | Зачётные номера студентов в приказе уникальны | здравый смысл |
| R-07 | Тип практики (учебная / производственная) указан явно | стр. 3 |
| R-08 | Если место практики — профильная организация, то она должна быть в списке организаций ФИТ | стр. 5–6, сноска про договор |
| R-09 | Курс совместим с программой: для 09.03.01 курс ∈ {1..4}, для 09.04.01 курс ∈ {1..2} | ФГОС, общие нормы |
| R-10 | Приказ согласован деканом факультета | пример приказа, лист согласования |

Покрытие в MVP: **R-01 — R-07 обязательно**, R-08 — R-10 — если LLM сможет распарсить нужные данные.

## 5. Нефункциональные требования

| Категория | Требование |
|---|---|
| Локальный запуск | Работает без интернета, кроме вызовов OpenRouter |
| LLM-агностичность | Заменить модель = поменять имя в `.env`, без правки кода |
| Расширяемость | Новый регламент = новый `.owl` файл, без изменения ядра |
| Воспроизводимость | Скрипт `scripts/build_ontology.py` детерминирован при фиксированной модели и temperature=0 |
| Прозрачность правил | Каждое нарушение в отчёте сопровождается текстом правила и (если есть) пунктом регламента |

## 6. Технические риски

| Риск | Вероятность | Митигация |
|---|---|---|
| OCR-качество приказа недостаточно | средняя | Используем не tesseract (его нет без apt), а LLM с vision-возможностями (читает рендеры PNG) |
| HermiT не справляется со сложными SWRL-правилами | низкая | Откат на Pellet или замена SWRL на DL-аксиомы |
| Бесплатные лимиты OpenRouter закончатся | низкая | Прогон через несколько моделей, кэш по хешу страницы |
| LLM выдаёт «галлюцинированные» сущности на этапе build-time | высокая | Аналитик ручную правку в Protégé делает явно — это не bug, а feature процесса |
| Сканы приказов очень разные по формату | средняя | Считаем только формат НГУ-ФИТ. Другие — out of scope MVP |

## 7. Что вне скоупа

- Не делаем парсинг отчётов о практике, отзывов, индивидуальных заданий — только приказ.
- Не делаем интеграцию с 1С/документооборотом НГУ.
- Не делаем редактирование онтологии через UI (только через Protégé на этапе подготовки).
- Не делаем учётные записи / роли / аутентификацию.
- Не делаем продовый деплой — это локальный прототип.
